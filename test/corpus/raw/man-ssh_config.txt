[1mNAME[0m
       ssh_config — OpenSSH client configuration file

[1mDESCRIPTION[0m
       [4mssh[24m(1) obtains configuration data from the following sources in the following order:

             1.   command-line options
             2.   user's configuration file ([4m~/.ssh/config[24m)
             3.   system-wide configuration file ([4m/etc/ssh/ssh_config[24m)

       Unless  noted otherwise, for each parameter, the first obtained value will be used.  The con‐
       figuration files contain sections separated by [1mHost [22mspecifications, and that section is  only
       applied  for  hosts  that  match one of the patterns given in the specification.  The matched
       host name is usually the one given on the command line (see the  [1mCanonicalizeHostname  [22moption
       for exceptions).

       Since  the  first  obtained value for each parameter is used, more host-specific declarations
       should be given near the beginning of the file, and general defaults at the end.

       Note  that  the  Debian  [1mopenssh-client  [22mpackage  sets  several  options   as   standard   in
       [4m/etc/ssh/ssh_config[24m which are not the default in [4mssh[24m(1):

             [1m•   Include /etc/ssh/ssh_config.d/*.conf[0m
             [1m•   SendEnv [22mLANG LC_*
             [1m•   HashKnownHosts [22myes
             [1m•   GSSAPIAuthentication [22myes

       [4m/etc/ssh/ssh_config.d/*.conf[24m files are included at the start of the system-wide configuration
       file, so options set there will override those in [4m/etc/ssh/ssh_config.[0m

       The  file  contains  keyword-argument pairs, one per line.  Lines starting with ‘#’ and empty
       lines are interpreted as comments.  Arguments may optionally be enclosed in double quotes (")
       in order to represent arguments containing spaces.  Configuration options may be separated by
       whitespace or optional whitespace and exactly one ‘=’; the latter format is useful  to  avoid
       the  need  to  quote whitespace when specifying configuration options using the [1mssh[22m, [1mscp[22m, and
       [1msftp -o [22moption.

       The possible keywords and their meanings are as follows (note that keywords are case-insensi‐
       tive and arguments are case-sensitive):

       [1mHost    [22mRestricts the following declarations (up to the next [1mHost [22mor  [1mMatch  [22mkeyword)  to  be
               only for those hosts that match one of the patterns given after the keyword.  If more
               than  one  pattern is provided, they should be separated by whitespace.  A single ‘*’
               as a pattern can be used to provide global defaults for all hosts.  The host is  usu‐
               ally  the  [4mhostname[24m  argument given on the command line (see the [1mCanonicalizeHostname[0m
               keyword for exceptions).

               A pattern entry may be negated by prefixing it with an exclamation mark (‘!’).  If  a
               negated  entry  is matched, then the [1mHost [22mentry is ignored, regardless of whether any
               other patterns on the line match.  Negated matches are therefore  useful  to  provide
               exceptions for wildcard matches.

               See “PATTERNS” for more information on patterns.

       [1mMatch   [22mRestricts  the  following  declarations  (up to the next [1mHost [22mor [1mMatch [22mkeyword) to be
               used only when the conditions following the [1mMatch [22mkeyword are satisfied.  Match  con‐
               ditions are specified using one or more criteria or the single token [1mall [22mwhich always
               matches.   The available criteria keywords are: [1mcanonical[22m, [1mfinal[22m, [1mexec[22m, [1mlocalnetwork[22m,
               [1mhost[22m, [1moriginalhost[22m, [1mTag[22m, [1muser[22m, and [1mlocaluser[22m.  The [1mall [22mcriteria must appear alone  or
               immediately  after  [1mcanonical  [22mor [1mfinal[22m.  Other criteria may be combined arbitrarily.
               All criteria but [1mall[22m, [1mcanonical[22m, and [1mfinal [22mrequire  an  argument.   Criteria  may  be
               negated by prepending an exclamation mark (‘!’).

               The [1mcanonical [22mkeyword matches only when the configuration file is being re-parsed af‐
               ter  hostname  canonicalization  (see  the [1mCanonicalizeHostname [22moption).  This may be
               useful to specify conditions that work with canonical host names only.

               The [1mfinal [22mkeyword requests that the configuration be re-parsed (regardless of whether
               [1mCanonicalizeHostname [22mis enabled), and  matches  only  during  this  final  pass.   If
               [1mCanonicalizeHostname [22mis enabled, then [1mcanonical [22mand [1mfinal [22mmatch during the same pass.

               The  [1mexec [22mkeyword executes the specified command under the user's shell.  If the com‐
               mand returns a zero exit status then the condition is considered true.  Commands con‐
               taining whitespace characters must be quoted.  Arguments to [1mexec  [22maccept  the  tokens
               described in the “TOKENS” section.

               The  [1mlocalnetwork  [22mkeyword  matches  the addresses of active local network interfaces
               against the supplied list of networks in CIDR format.  This  may  be  convenient  for
               varying the effective configuration on devices that roam between networks.  Note that
               network  address is not a trustworthy criteria in many situations (e.g. when the net‐
               work is automatically configured using DHCP) and so caution should be applied if  us‐
               ing it to control security-sensitive configuration.

               The  other keywords' criteria must be single entries or comma-separated lists and may
               use the wildcard and negation operators described in  the  “PATTERNS”  section.   The
               criteria for the [1mhost [22mkeyword are matched against the target hostname, after any sub‐
               stitution  by the [1mHostname [22mor [1mCanonicalizeHostname [22moptions.  The [1moriginalhost [22mkeyword
               matches against the hostname as it was specified on  the  command-line.   The  [1mtagged[0m
               keyword  matches  a tag name specified by a prior [1mTag [22mdirective or on the [4mssh[24m(1) com‐
               mand-line using the [1m-P [22mflag.  The [1muser [22mkeyword matches against the target username on
               the remote host.  The [1mlocaluser [22mkeyword matches against the name of  the  local  user
               running [4mssh[24m(1) (this keyword may be useful in system-wide [1mssh_config [22mfiles).

       [1mAddKeysToAgent[0m
               Specifies  whether  keys should be automatically added to a running [4mssh-agent[24m(1).  If
               this option is set to [1myes [22mand a key is loaded from a file, the key and its passphrase
               are added to the agent with the default lifetime, as if by [4mssh-add[24m(1).  If  this  op‐
               tion  is  set  to [1mask[22m, [4mssh[24m(1) will require confirmation using the SSH_ASKPASS program
               before adding a key (see [4mssh-add[24m(1) for details).  If this option is set to  [1mconfirm[22m,
               each  use  of  the  key  must  be  confirmed,  as  if  the [1m-c [22moption was specified to
               [4mssh-add[24m(1).  If this option is set to [1mno[22m, no keys are added  to  the  agent.   Alter‐
               nately, this option may be specified as a time interval using the format described in
               the  “TIME  FORMATS”  section  of  [4msshd_config[24m(5)  to  specify  the key's lifetime in
               [4mssh-agent[24m(1), after which it will automatically be removed.  The argument must be  [1mno[0m
               (the  default),  [1myes[22m, [1mconfirm [22m(optionally followed by a time interval), [1mask [22mor a time
               interval.

       [1mAddressFamily[0m
               Specifies which address family to use when connecting.  Valid arguments are [1many  [22m(the
               default), [1minet [22m(use IPv4 only), or [1minet6 [22m(use IPv6 only).

       [1mBatchMode[0m
               If  set  to  [1myes[22m, user interaction such as password prompts and host key confirmation
               requests will be disabled.  In addition, the [1mServerAliveInterval [22moption will  be  set
               to  300  seconds  by default (Debian-specific).  This option is useful in scripts and
               other batch jobs where no user is present to interact with [4mssh[24m(1), and  where  it  is
               desirable  to  detect  a broken network swiftly.  The argument must be [1myes [22mor [1mno [22m(the
               default).

       [1mBindAddress[0m
               Use the specified address on the local machine as the source address of  the  connec‐
               tion.  Only useful on systems with more than one address.

       [1mBindInterface[0m
               Use the address of the specified interface on the local machine as the source address
               of the connection.

       [1mCanonicalDomains[0m
               When  [1mCanonicalizeHostname  [22mis enabled, this option specifies the list of domain suf‐
               fixes in which to search for the specified destination host.

       [1mCanonicalizeFallbackLocal[0m
               Specifies whether to fail with an error when hostname  canonicalization  fails.   The
               default,  [1myes[22m,  will attempt to look up the unqualified hostname using the system re‐
               solver's search rules.  A value  of  [1mno  [22mwill  cause  [4mssh[24m(1)  to  fail  instantly  if
               [1mCanonicalizeHostname [22mis enabled and the target hostname cannot be found in any of the
               domains specified by [1mCanonicalDomains[22m.

       [1mCanonicalizeHostname[0m
               Controls  whether  explicit hostname canonicalization is performed.  The default, [1mno[22m,
               is not to perform any name rewriting and let the system resolver handle all  hostname
               lookups.   If  set  to  [1myes  [22mthen,  for connections that do not use a [1mProxyCommand [22mor
               [1mProxyJump[22m, [4mssh[24m(1) will attempt to canonicalize the hostname specified on the  command
               line  using  the [1mCanonicalDomains [22msuffixes and [1mCanonicalizePermittedCNAMEs [22mrules.  If
               [1mCanonicalizeHostname [22mis set to [1malways[22m, then canonicalization is  applied  to  proxied
               connections too.

               If this option is enabled, then the configuration files are processed again using the
               new  target name to pick up any new configuration in matching [1mHost [22mand [1mMatch [22mstanzas.
               A value of [1mnone [22mdisables the use of a [1mProxyJump [22mhost.

       [1mCanonicalizeMaxDots[0m
               Specifies the maximum number of dot characters in a hostname before  canonicalization
               is disabled.  The default, 1, allows a single dot (i.e. hostname.subdomain).

       [1mCanonicalizePermittedCNAMEs[0m
               Specifies  rules  to  determine whether CNAMEs should be followed when canonicalizing
               hostnames.     The    rules    consist    of    one    or    more    arguments     of
               [4msource_domain_list[24m:[4mtarget_domain_list[24m,  where [4msource_domain_list[24m is a pattern-list of
               domains that may follow CNAMEs in canonicalization, and [4mtarget_domain_list[24m is a  pat‐
               tern-list of domains that they may resolve to.

               For  example,  "*.a.example.com:*.b.example.com,*.c.example.com" will allow hostnames
               matching "*.a.example.com" to be canonicalized to names in the  "*.b.example.com"  or
               "*.c.example.com" domains.

               A  single  argument of "none" causes no CNAMEs to be considered for canonicalization.
               This is the default behaviour.

       [1mCASignatureAlgorithms[0m
               Specifies which algorithms are allowed for signing of certificates by certificate au‐
               thorities (CAs).  The default is:

                     ssh-ed25519,ecdsa-sha2-nistp256,
                     ecdsa-sha2-nistp384,ecdsa-sha2-nistp521,
                     sk-ssh-ed25519@openssh.com,
                     sk-ecdsa-sha2-nistp256@openssh.com,
                     rsa-sha2-512,rsa-sha2-256

               If the specified list begins with a ‘+’ character, then the specified algorithms will
               be appended to the default set instead of replacing them.  If the specified list  be‐
               gins  with  a ‘-’ character, then the specified algorithms (including wildcards) will
               be removed from the default set instead of replacing them.

               [4mssh[24m(1) will not accept host certificates signed using  algorithms  other  than  those
               specified.

       [1mCertificateFile[0m
               Specifies  a file from which the user's certificate is read.  A corresponding private
               key must be provided separately in order to  use  this  certificate  either  from  an
               [1mIdentityFile   [22mdirective   or   [1m-i  [22mflag  to  [4mssh[24m(1),  via  [4mssh-agent[24m(1),  or  via  a
               [1mPKCS11Provider [22mor [1mSecurityKeyProvider[22m.

               Arguments to [1mCertificateFile [22mmay use the tilde syntax to refer to a user's  home  di‐
               rectory,  the  tokens  described in the “TOKENS” section and environment variables as
               described in the “ENVIRONMENT VARIABLES” section.

               It is possible to have multiple certificate files specified in  configuration  files;
               these  certificates  will  be tried in sequence.  Multiple [1mCertificateFile [22mdirectives
               will add to the list of certificates used for authentication.

       [1mChannelTimeout[0m
               Specifies whether and how quickly [4mssh[24m(1) should close  inactive  channels.   Timeouts
               are specified as one or more “type=interval” pairs separated by whitespace, where the
               “type” must be a channel type name (as described in the table below), optionally con‐
               taining wildcard characters.

               The timeout value “interval” is specified in seconds or may use any of the units doc‐
               umented in the “TIME FORMATS” section.  For example, “session=5m” would cause the in‐
               teractive  session  to terminate after five minutes of inactivity.  Specifying a zero
               value disables the inactivity timeout.

               The available channel types include:

               [1magent-connection[0m
                       Open connections to [4mssh-agent[24m(1).

               [1mdirect-tcpip[22m, [1mdirect-streamlocal@openssh.com[0m
                       Open TCP or Unix socket (respectively) connections that have been established
                       from a [4mssh[24m(1) local forwarding, i.e. [1mLocalForward [22mor [1mDynamicForward[22m.

               [1mforwarded-tcpip[22m, [1mforwarded-streamlocal@openssh.com[0m
                       Open TCP or Unix socket (respectively) connections that have been established
                       to a [4msshd[24m(8)  listening  on  behalf  of  a  [4mssh[24m(1)  remote  forwarding,  i.e.
                       [1mRemoteForward[22m.

               [1msession[0m
                       The  interactive  main  session,  including shell session, command execution,
                       [4mscp[24m(1), [4msftp[24m(1), etc.

               [1mtun-connection[0m
                       Open [1mTunnelForward [22mconnections.

               [1mx11-connection[0m
                       Open X11 forwarding sessions.

               Note that in all the above cases, terminating an inactive session does not  guarantee
               to  remove  all  resources  associated  with the session, e.g. shell processes or X11
               clients relating to the session may continue to execute.

               Moreover, terminating an inactive channel or session does not necessarily  close  the
               SSH  connection,  nor does it prevent a client from requesting another channel of the
               same type.  In particular, expiring an inactive forwarding session does  not  prevent
               another identical forwarding from being subsequently created.

               The default is not to expire channels of any type for inactivity.

       [1mCheckHostIP[0m
               If  set to [1myes[22m, [4mssh[24m(1) will additionally check the host IP address in the [4mknown_hosts[0m
               file.  This allows it to detect if a host key changed due to DNS  spoofing  and  will
               add  addresses  of destination hosts to [4m~/.ssh/known_hosts[24m in the process, regardless
               of the setting of [1mStrictHostKeyChecking[22m.  If the option is set to [1mno  [22m(the  default),
               the check will not be executed.

       [1mCiphers[0m
               Specifies  the  ciphers allowed and their order of preference.  Multiple ciphers must
               be comma-separated.  If the specified list begins with  a  ‘+’  character,  then  the
               specified  ciphers will be appended to the default set instead of replacing them.  If
               the specified list begins with a ‘-’ character, then the specified ciphers (including
               wildcards) will be removed from the default set instead of replacing  them.   If  the
               specified list begins with a ‘^’ character, then the specified ciphers will be placed
               at the head of the default set.

               The supported ciphers are:

                     3des-cbc
                     aes128-cbc
                     aes192-cbc
                     aes256-cbc
                     aes128-ctr
                     aes192-ctr
                     aes256-ctr
                     aes128-gcm@openssh.com
                     aes256-gcm@openssh.com
                     chacha20-poly1305@openssh.com

               The default is:

                     chacha20-poly1305@openssh.com,
                     aes128-ctr,aes192-ctr,aes256-ctr,
                     aes128-gcm@openssh.com,aes256-gcm@openssh.com

               The list of available ciphers may also be obtained using "ssh -Q cipher".

       [1mClearAllForwardings[0m
               Specifies  that all local, remote, and dynamic port forwardings specified in the con‐
               figuration files or on the command line be cleared.  This option is primarily  useful
               when used from the [4mssh[24m(1) command line to clear port forwardings set in configuration
               files,  and  is automatically set by [4mscp[24m(1) and [4msftp[24m(1).  The argument must be [1myes [22mor
               [1mno [22m(the default).

       [1mCompression[0m
               Specifies whether to use compression.  The argument must be [1myes [22mor [1mno [22m(the default).

       [1mConnectionAttempts[0m
               Specifies the number of tries (one per second) to make before exiting.  The  argument
               must be an integer.  This may be useful in scripts if the connection sometimes fails.
               The default is 1.

       [1mConnectTimeout[0m
               Specifies the timeout (in seconds) used when connecting to the SSH server, instead of
               using  the  default system TCP timeout.  This timeout is applied both to establishing
               the connection and to performing the initial SSH protocol handshake and key exchange.

       [1mControlMaster[0m
               Enables the sharing of multiple sessions over a single network connection.  When  set
               to  [1myes[22m,  [4mssh[24m(1)  will listen for connections on a control socket specified using the
               [1mControlPath [22margument.  Additional sessions can connect to this socket using the  same
               [1mControlPath  [22mwith  [1mControlMaster [22mset to [1mno [22m(the default).  These sessions will try to
               reuse the master instance's network connection rather than initiating new  ones,  but
               will fall back to connecting normally if the control socket does not exist, or is not
               listening.

               Setting  this to [1mask [22mwill cause [4mssh[24m(1) to listen for control connections, but require
               confirmation using [4mssh-askpass[24m(1).  If the [1mControlPath [22mcannot be opened, [4mssh[24m(1)  will
               continue without connecting to a master instance.

               X11 and [4mssh-agent[24m(1) forwarding is supported over these multiplexed connections, how‐
               ever  the display and agent forwarded will be the one belonging to the master connec‐
               tion i.e. it is not possible to forward multiple displays or agents.

               Two additional options allow for opportunistic multiplexing: try to use a master con‐
               nection but fall back to creating a new one if one does not already exist.  These op‐
               tions are: [1mauto [22mand [1mautoask[22m.  The latter requires confirmation like the [1mask [22moption.

       [1mControlPath[0m
               Specify the path to the control socket used for connection sharing  as  described  in
               the  [1mControlMaster  [22msection  above  or the string [1mnone [22mto disable connection sharing.
               Arguments to [1mControlPath [22mmay use the tilde syntax to refer to a  user's  home  direc‐
               tory,  the  tokens described in the “TOKENS” section and environment variables as de‐
               scribed  in  the  “ENVIRONMENT  VARIABLES”  section.   It  is  recommended  that  any
               [1mControlPath [22mused for opportunistic connection sharing include at least %h, %p, and %r
               (or  alternatively  %C)  and  be  placed in a directory that is not writable by other
               users.  This ensures that shared connections are uniquely identified.

       [1mControlPersist[0m
               When used in conjunction with [1mControlMaster[22m, specifies  that  the  master  connection
               should  remain  open  in the background (waiting for future client connections) after
               the initial client connection has been closed.  If set to [1mno [22m(the default), then  the
               master  connection  will not be placed into the background, and will close as soon as
               the initial client connection is closed.  If set to [1myes [22mor 0, then the master connec‐
               tion will remain in the background indefinitely (until killed or closed via a  mecha‐
               nism  such  as  the "ssh -O exit").  If set to a time in seconds, or a time in any of
               the formats documented in [4msshd_config[24m(5), then  the  backgrounded  master  connection
               will  automatically terminate after it has remained idle (with no client connections)
               for the specified time.

       [1mDynamicForward[0m
               Specifies that a TCP port on the local machine be forwarded over the secure  channel,
               and  the  application protocol is then used to determine where to connect to from the
               remote machine.

               The argument must be [[4mbind_address[24m:][4mport[24m.  IPv6 addresses can be specified by enclos‐
               ing addresses in square brackets.  By default, the local port is bound in  accordance
               with the [1mGatewayPorts [22msetting.  However, an explicit [4mbind_address[24m may be used to bind
               the  connection  to a specific address.  The [4mbind_address[24m of [1mlocalhost [22mindicates that
               the listening port be bound for local use only, while an empty address or  ‘*’  indi‐
               cates that the port should be available from all interfaces.

               Currently  the  SOCKS4  and  SOCKS5 protocols are supported, and [4mssh[24m(1) will act as a
               SOCKS server.  Multiple forwardings may be specified, and additional forwardings  can
               be given on the command line.  Only the superuser can forward privileged ports.

       [1mEnableEscapeCommandline[0m
               Enables  the command line option in the [1mEscapeChar [22mmenu for interactive sessions (de‐
               fault ‘~C’).  By default, the command line is disabled.

       [1mEnableSSHKeysign[0m
               Setting  this   option   to   [1myes   [22min   the   global   client   configuration   file
               [4m/etc/ssh/ssh_config[24m  enables  the  use  of  the  helper program [4mssh-keysign[24m(8) during
               [1mHostbasedAuthentication[22m.  The argument must be [1myes [22mor [1mno [22m(the default).  This  option
               should be placed in the non-hostspecific section.  See [4mssh-keysign[24m(8) for more infor‐
               mation.

       [1mEscapeChar[0m
               Sets  the  escape  character (default: ‘~’).  The escape character can also be set on
               the command line.  The argument should be a single character, ‘^’ followed by a  let‐
               ter,  or  [1mnone [22mto disable the escape character entirely (making the connection trans‐
               parent for binary data).

       [1mExitOnForwardFailure[0m
               Specifies whether [4mssh[24m(1) should terminate the connection if it cannot set up all  re‐
               quested  dynamic,  tunnel, local, and remote port forwardings, (e.g. if either end is
               unable to bind and listen on a specified port).  Note that [1mExitOnForwardFailure  [22mdoes
               not  apply to connections made over port forwardings and will not, for example, cause
               [4mssh[24m(1) to exit if TCP connections to the ultimate forwarding destination  fail.   The
               argument must be [1myes [22mor [1mno [22m(the default).

       [1mFingerprintHash[0m
               Specifies  the  hash  algorithm used when displaying key fingerprints.  Valid options
               are: [1mmd5 [22mand [1msha256 [22m(the default).

       [1mForkAfterAuthentication[0m
               Requests [1mssh [22mto go to background just before command execution.  This  is  useful  if
               [1mssh  [22mis going to ask for passwords or passphrases, but the user wants it in the back‐
               ground.  This implies the [1mStdinNull [22mconfiguration option being  set  to  “yes”.   The
               recommended  way to start X11 programs at a remote site is with something like [1mssh -f[0m
               [1mhost xterm[22m, which is the same as [1mssh host xterm [22mif the  [1mForkAfterAuthentication  [22mcon‐
               figuration option is set to “yes”.

               If  the  [1mExitOnForwardFailure  [22mconfiguration  option  is  set to “yes”, then a client
               started with the [1mForkAfterAuthentication [22mconfiguration option being set to “yes” will
               wait for all remote port forwards to be successfully established before  placing  it‐
               self in the background.  The argument to this keyword must be [1myes [22m(same as the [1m-f [22mop‐
               tion) or [1mno [22m(the default).

       [1mForwardAgent[0m
               Specifies  whether  the  connection to the authentication agent (if any) will be for‐
               warded to the remote machine.  The argument may be [1myes[22m, [1mno [22m(the default), an explicit
               path to an agent socket or the name of an environment variable (beginning  with  ‘$’)
               in which to find the path.

               Agent  forwarding  should  be enabled with caution.  Users with the ability to bypass
               file permissions on the remote host (for the agent's Unix-domain socket)  can  access
               the  local agent through the forwarded connection.  An attacker cannot obtain key ma‐
               terial from the agent, however they can perform operations on the  keys  that  enable
               them to authenticate using the identities loaded into the agent.

       [1mForwardX11[0m
               Specifies  whether  X11  connections will be automatically redirected over the secure
               channel and DISPLAY set.  The argument must be [1myes [22mor [1mno [22m(the default).

               X11 forwarding should be enabled with caution.  Users with the ability to bypass file
               permissions on the remote host (for the user's X11 authorization database) can access
               the local X11 display through the forwarded connection.  An attacker may then be able

       [1mServerAliveCountMax[0m
               Sets the number of server alive messages (see below) which may be sent without [4mssh[24m(1)
               receiving  any  messages  back  from  the server.  If this threshold is reached while
               server alive messages are being sent, ssh will disconnect from the server,  terminat‐
               ing  the  session.   It is important to note that the use of server alive messages is
               very different from [1mTCPKeepAlive [22m(below).  The server alive messages are sent through
               the encrypted channel and therefore will not be spoofable.  The TCP keepalive  option
               enabled  by  [1mTCPKeepAlive  [22mis spoofable.  The server alive mechanism is valuable when
               the client or server depend on knowing when a connection has become unresponsive.

               The default value is 3.  If, for example, [1mServerAliveInterval [22m(see below) is  set  to
               15  and  [1mServerAliveCountMax  [22mis left at the default, if the server becomes unrespon‐
               sive, ssh will disconnect after approximately 45 seconds.

       [1mServerAliveInterval[0m

               server,  [4mssh[24m(1)  will  send  a message through the encrypted channel to request a re‐
               sponse from the server.  The default is 0, indicating that these messages will not be
               sent to the server,  or  300  if  the  [1mBatchMode  [22moption  is  set  (Debian-specific).
               [1mProtocolKeepAlives  [22mand  [1mSetupTimeOut  [22mare  Debian-specific compatibility aliases for
               this option.

               If this flag is set to [1myes[22m, [4mssh[24m(1) will never automatically  add  host  keys  to  the

               the user's [4mknown_hosts[24m file, but will not permit connections to  hosts  with  changed
               host  keys.   If  this  flag is set to [1mno [22mor [1moff[22m, ssh will automatically add new host

               hostkeys  to  proceed, subject to some restrictions.  If this flag is set to [1mask [22m(the

               user  has  confirmed that is what they really want to do, and ssh will refuse to con‐

       [1mTCPKeepAlive[0m

               To  disable  TCP  keepalive  messages,  the  value  should  be  set  to [1mno[22m.  See also
               [1mServerAliveInterval [22mfor protocol-level keepalives.

[1mPATTERNS[0m
       A  [4mpattern[24m  consists  of zero or more non-whitespace characters, ‘*’ (a wildcard that matches
       zero or more characters), or ‘?’ (a wildcard that matches exactly one character).  For  exam‐
       ple,  to  specify a set of declarations for any host in the ".co.uk" set of domains, the fol‐
       lowing pattern could be used:

             [1mHost *.co.uk[0m

       The following pattern would match any host in the 192.168.0.[0-9] network range:

             [1mHost 192.168.0.?[0m

       A [4mpattern-list[24m is a comma-separated list of patterns.  Patterns within pattern-lists  may  be
       negated  by preceding them with an exclamation mark (‘!’).  For example, to allow a key to be
       used from anywhere within an organization except from the "dialup" pool, the following  entry
       (in authorized_keys) could be used:

             [1mfrom="!*.dialup.example.com,*.example.com"[0m

       Note  that  a negated match will never produce a positive result by itself.  For example, at‐
       tempting to match "host3" against the following pattern-list will fail:

             [1mfrom="!host1,!host2"[0m

       The solution here is to include a term that will yield a positive match, such as a wildcard:

             [1mfrom="!host1,!host2,*"[0m

[1mTOKENS[0m
       Arguments to some keywords can make use of tokens, which are expanded at runtime:

             %%    A literal ‘%’.
             %C    Hash of %l%h%p%r%j.
             %d    Local user's home directory.
             %f    The fingerprint of the server's host key.
             %H    The [4mknown_hosts[24m hostname or address that is being searched for.
             %h    The remote hostname.
             %I    A string describing the reason for a [1mKnownHostsCommand [22mexecution: either  [1mADDRESS[0m
                   when  looking  up  a host by address (only when [1mCheckHostIP [22mis enabled), [1mHOSTNAME[0m
                   when searching by hostname, or [1mORDER [22mwhen preparing the host key algorithm  pref‐
                   erence list to use for the destination host.
             %i    The local user ID.
             %j    The  contents  of the ProxyJump option, or the empty string if this option is un‐
                   set.
             %K    The base64 encoded host key.
             %k    The host key alias if specified, otherwise the original remote hostname given  on
                   the command line.
             %L    The local hostname.
             %l    The local hostname, including the domain name.
             %n    The original remote hostname, as given on the command line.
             %p    The remote port.
             %r    The remote username.
             %T    The  local  [4mtun[24m(4)  or [4mtap[24m(4) network interface assigned if tunnel forwarding was
                   requested, or "NONE" otherwise.
             %t    The type of the server host key, e.g.  [1mssh-ed25519[22m.
             %u    The local username.

       [1mCertificateFile[22m, [1mControlPath[22m, [1mIdentityAgent[22m, [1mIdentityFile[22m,  [1mKnownHostsCommand[22m,  [1mLocalForward[22m,
       [1mMatch  exec[22m, [1mRemoteCommand[22m, [1mRemoteForward[22m, [1mRevokedHostKeys[22m, and [1mUserKnownHostsFile [22maccept the
       tokens %%, %C, %d, %h, %i, %j, %k, %L, %l, %n, %p, %r, and %u.

       [1mKnownHostsCommand [22madditionally accepts the tokens %f, %H, %I, %K and %t.

       [1mHostname [22maccepts the tokens %% and %h.

       [1mLocalCommand [22maccepts all tokens.

       [1mProxyCommand [22mand [1mProxyJump [22maccept the tokens %%, %h, %n, %p, and %r.

       Note that some of these directives build commands  for  execution  via  the  shell.   Because
       [4mssh[24m(1)  performs  no  filtering  or escaping of characters that have special meaning in shell
       commands (e.g. quotes), it is the user's responsibility to ensure that the  arguments  passed
       to [4mssh[24m(1) do not contain such characters and that tokens are appropriately quoted when used.

[1mENVIRONMENT VARIABLES[0m
       Arguments  to  some  keywords  can  be  expanded at runtime from environment variables on the
       client by enclosing them in [1m${}[22m, for example [1m${HOME}/.ssh [22mwould refer to the user's .ssh  di‐
       rectory.   If  a specified environment variable does not exist then an error will be returned
       and the setting for that keyword will be ignored.

       The keywords [1mCertificateFile[22m, [1mControlPath[22m,  [1mIdentityAgent[22m,  [1mIdentityFile[22m,  [1mKnownHostsCommand[22m,
       and   [1mUserKnownHostsFile  [22msupport  environment  variables.   The  keywords  [1mLocalForward  [22mand
       [1mRemoteForward [22msupport environment variables only for Unix domain socket paths.
