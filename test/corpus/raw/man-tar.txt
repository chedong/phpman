[1mDESCRIPTION[0m
       GNU  [1mtar  [22mis  an  archiving  program  designed  to  store multiple files in a single file (an
       [1marchive[22m), and to manipulate such archives.  The archive can be either a regular file or a de‐
       vice (e.g. a tape drive, hence the name of the program,  which  stands  for  [1mt[22mape  [1mar[22mchiver),
       which can be located either on the local or on a remote machine.

   [1mOption styles[0m
       Options  to  GNU [1mtar [22mcan be given in three different styles.  In [1mtraditional style[22m, the first
       argument is a cluster of option letters and all  subsequent  arguments  supply  arguments  to
       those options that require them.  The arguments are read in the same order as the option let‐
       ters.   Any  command line words that remain after all options have been processed are treated
       as non-option arguments: file or archive member names.

       For example, the [1mc [22moption requires creating the archive, the [1mv [22moption  requests  the  verbose
       operation,  and  the  [1mf [22moption takes an argument that sets the name of the archive to operate
       upon.  The following command, written in the traditional style, instructs tar  to  store  all
       files  from the directory [1m/etc [22minto the archive file [1metc.tar[22m, verbosely listing the files be‐
       ing archived:

       tar cfv etc.tar /etc

       In [1mUNIX [22mor [1mshort-option style[22m, each option letter is prefixed with a single dash, as in other
       command line utilities.  If an option takes an argument, the argument follows it, either as a
       separate command line word, or immediately following the  option.   However,  if  the  option
       takes  an [1moptional [22margument, the argument must follow the option letter without any interven‐
       ing whitespace, as in [1m-g/tmp/snar.db[22m.

       Any number of options not taking arguments can be clustered together  after  a  single  dash,
       e.g.  [1m-vkp[22m.   An  option that takes an argument (whether mandatory or optional) can appear at
       the end of such a cluster, e.g. [1m-vkpf a.tar[22m.

       The example command above written in the [1mshort-option style [22mcould look like:

       tar -cvf etc.tar /etc
       or
       tar -c -v -f etc.tar /etc

       In [1mGNU [22mor [1mlong-option style[22m, each option begins with two dashes and has  a  meaningful  name,
       consisting  of  lower-case letters and dashes.  When used, the long option can be abbreviated
       to its initial letters, provided that this does not create ambiguity.  Arguments to long  op‐
       tions  are supplied either as a separate command line word, immediately following the option,
       or separated from the option by an equals sign with no intervening whitespace.  Optional  ar‐
       guments must always use the latter method.

       Here are several ways of writing the example command in this style:

       tar --create --file etc.tar --verbose /etc
       or (abbreviating some options):
       tar --cre --file=etc.tar --verb /etc

       The  options in all three styles can be intermixed, although doing so with old options is not
       encouraged.

   [1mOperation mode[0m
       The options listed in the table below tell GNU [1mtar [22mwhat operation it is to perform.   Exactly
       one of them must be given.  The meaning of non-option arguments depends on the operation mode
       requested.

       [1m-A[22m, [1m--catenate[22m, [1m--concatenate[0m
              Append archives to the end of another archive.  The arguments are treated as the names
              of  archives  to  append.  All archives must be of the same format as the archive they
              are appended to, otherwise the resulting archive might be unusable with non-GNU imple‐
              mentations of [1mtar[22m.  Notice also that when more than one archive is given, the  members
              from  archives  other  than  the first one will be accessible in the resulting archive
              only when using the [1m-i [22m([1m--ignore-zeros[22m) option.

              Compressed archives cannot be concatenated.

       [1m-c[22m, [1m--create[0m
              Create a new archive.  Arguments supply the names of the files to be archived.  Direc‐
              tories are archived recursively, unless the [1m--no-recursion [22moption is given.

       [1m-d[22m, [1m--diff[22m, [1m--compare[0m
              Find differences between archive and file system.   The  arguments  are  optional  and
              specify  archive  members  to compare.  If not given, the current working directory is
              assumed.

       [1m--delete[0m
              Delete from the archive.  The arguments supply names of the archive members to be  re‐
              moved.  At least one argument must be given.

              This option does not operate on compressed archives.  There is no short option equiva‐
              lent.

       [1m-r[22m, [1m--append[0m
              Append  files  to  the  end  of an archive.  Arguments have the same meaning as for [1m-c[0m
              ([1m--create[22m).

       [1m-t[22m, [1m--list[0m
              List the contents of an archive.  Arguments are optional.  When  given,  they  specify
              the names of the members to list.

       [1m--test-label[0m
              Test  the  archive  volume label and exit.  When used without arguments, it prints the
              volume label (if any) and exits with status [1m0[22m.  When one or more  command  line  argu‐
              ments  are  given.   [1mtar  [22mcompares the volume label with each argument.  It exits with
              code [1m0 [22mif a match is found, and with code [1m1 [22motherwise.  No output is displayed, unless
              used together with the [1m-v [22m([1m--verbose[22m) option.

              There is no short option equivalent for this option.

       [1m-u[22m, [1m--update[0m
              Append files which are newer than the corresponding copy in  the  archive.   Arguments
              have  the  same meaning as with the [1m-c [22mand [1m-r [22moptions.  Notice, that newer files don't
              replace their old archive copies, but instead are appended to the end of archive.  The
              resulting archive can thus contain several members of the same name, corresponding  to
              various versions of the same file.

       [1m-x[22m, [1m--extract[22m, [1m--get[0m
              Extract  files  from  an  archive.   Arguments are optional.  When given, they specify
              names of the archive members to be extracted.

       [1m--show-defaults[0m
              Show built-in defaults for various [1mtar [22moptions and exit.

       [1m-?[22m, [1m--help[0m
              Display a short option summary and exit.

       [1m--usage[0m
              Display a list of available options and exit.

       [1m--version[0m
              Print program version and copyright information and exit.

[1mOPTIONS[0m
   [1mOperation modifiers[0m
       [1m--check-device[0m
              Check device numbers when creating incremental archives (default).

       [1m-g[22m, [1m--listed-incremental[22m=[4mFILE[0m
              Handle new GNU-format incremental backups.  [4mFILE[24m is the name of a [1msnapshot file[22m, where
              [1mtar [22mstores additional information which is used to decide which  files  changed  since
              the  previous  incremental dump and, consequently, must be dumped again.  If [4mFILE[24m does
              not exist when creating an archive, it will be created and all files will be added  to
              the  resulting archive (the [1mlevel 0 [22mdump).  To create incremental archives of non-zero
              level [1mN[22m, you need a copy of the snapshot file created for level [1mN-1[22m,  and  use  it  as
              [4mFILE[24m.

              When  listing or extracting, the actual content of [4mFILE[24m is not inspected, it is needed
              only due to  syntactical  requirements.   It  is  therefore  common  practice  to  use
              [1m/dev/null [22min its place.

       [1m--hole-detection[22m=[4mMETHOD[0m
              Use [4mMETHOD[24m to detect holes in sparse files.  This option implies [1m--sparse[22m.  Valid val‐
              ues  for  [4mMETHOD[24m  are [1mseek [22mand [1mraw[22m.  Default is [1mseek [22mwith fallback to [1mraw [22mwhen not ap‐
              plicable.

       [1m-G[22m, [1m--incremental[0m
              Handle old GNU-format incremental backups.

       [1m--ignore-failed-read[0m
              Do not exit with nonzero on unreadable files.

       [1m--level[22m=[4mNUMBER[0m
              Set dump level for a created listed-incremental archive.  Currently only [1m--level=0  [22mis
              meaningful:  it  instructs  [1mtar  [22mto truncate the snapshot file before dumping, thereby
              forcing a level 0 dump.

       [1m-n[22m, [1m--seek[0m
              Assume the archive is seekable.  Normally [1mtar  [22mdetermines  automatically  whether  the
              archive  can  be  seeked  or  not.  This option is intended for use in cases when such
              recognition fails.  It takes effect only if the archive is open for reading (e.g. with
              [1m--list [22mor [1m--extract [22moptions).

       [1m--no-check-device[0m
              Do not check device numbers when creating incremental archives.

       [1m--no-seek[0m
              Assume the archive is not seekable.

       [1m--occurrence[22m[=[4mN[24m]
              Process only the [4mN[24mth occurrence of each file in the archive.   This  option  is  valid
              only  when  used with one of the following subcommands: [1m--delete[22m, [1m--diff[22m, [1m--extract [22mor
              [1m--list [22mand when a list of files is given either on the command line or via the [1m-T  [22mop‐
              tion.  The default [4mN[24m is [1m1[22m.

       [1m--restrict[0m
              Disable the use of some potentially harmful options.

       [1m--sparse-version[22m=[4mMAJOR[24m[.[4mMINOR[24m]
              Set  which  version of the sparse format to use.  This option implies [1m--sparse[22m.  Valid
              argument values are [1m0.0[22m, [1m0.1[22m, and [1m1.0[22m.  For a detailed discussion of  sparse  formats,
              refer  to the [1mGNU Tar Manual[22m, appendix [1mD[22m, "[1mSparse Formats[22m".  Using the [1minfo [22mreader, it
              can be accessed running the following command: [1minfo tar 'Sparse Formats'[22m.

       [1m-S[22m, [1m--sparse[0m
              Handle sparse files efficiently.  Some files in the  file  system  may  have  segments
              which  were  actually  never  written (quite often these are database files created by
              such systems as [1mDBM[22m).  When given this option, [1mtar [22mattempts to determine if  the  file
              is  sparse  prior  to archiving it, and if so, to reduce the resulting archive size by
              not dumping empty parts of the file.

   [1mOverwrite control[0m
       These options control [1mtar [22mactions when extracting a file over an existing copy on disk.

       [1m-k[22m, [1m--keep-old-files[0m
              Don't replace existing files when extracting.

       [1m--keep-newer-files[0m
              Don't replace existing files that are newer than their archive copies.

       [1m--keep-directory-symlink[0m
              Don't replace existing symlinks to directories when extracting.

       [1m--no-overwrite-dir[0m
              Preserve metadata of existing directories.

       [1m--one-top-level[22m[[1m=[4m[22mDIR[24m]
              Extract all files into [4mDIR[24m, or, if used without argument, into a subdirectory named by
              the base name of the archive (minus  standard  compression  suffixes  recognizable  by
              [1m--auto-compress).[0m

       [1m--overwrite[0m
              Overwrite existing files when extracting.

       [1m--overwrite-dir[0m
              Overwrite metadata of existing directories when extracting (default).

       [1m--recursive-unlink[0m
              Recursively remove all files in the directory prior to extracting it.

       [1m--remove-files[0m
              Remove files from disk after adding them to the archive.

       [1m--skip-old-files[0m
              Don't replace existing files when extracting, silently skip over them.

       [1m-U[22m, [1m--unlink-first[0m
              Remove each file prior to extracting over it.

       [1m-W[22m, [1m--verify[0m
              Verify the archive after writing it.

   [1mOutput stream selection[0m
       [1m--ignore-command-error[0m
              Ignore subprocess exit codes.

       [1m--no-ignore-command-error[0m
              Treat non-zero exit codes of children as error (default).

       [1m-O[22m, [1m--to-stdout[0m
              Extract files to standard output.

       [1m--to-command[22m=[4mCOMMAND[0m
              Pipe extracted files to [4mCOMMAND[24m.  The argument is the pathname of an external program,
              optionally  with command line arguments.  The program will be invoked and the contents
              of the file being extracted supplied to it on its  standard  input.   Additional  data
              will be supplied via the following environment variables:

              [1mTAR_FILETYPE[0m
                     Type of the file. It is a single letter with the following meaning:

                             f           Regular file
                             d           Directory
                             l           Symbolic link
                             h           Hard link
                             b           Block device
                             c           Character device

                     Currently only regular files are supported.

              [1mTAR_MODE[0m
                     File mode, an octal number.

              [1mTAR_FILENAME[0m
                     The name of the file.

              [1mTAR_REALNAME[0m
                     Name of the file as stored in the archive.

              [1mTAR_UNAME[0m
                     Name of the file owner.

              [1mTAR_GNAME[0m
                     Name of the file owner group.

              [1mTAR_ATIME[0m
                     Time  of  last  access.  It is a decimal number, representing seconds since the
                     Epoch.  If the archive provides times with nanosecond precision,  the  nanosec‐
                     onds are appended to the timestamp after a decimal point.

              [1mTAR_MTIME[0m
                     Time of last modification.

              [1mTAR_CTIME[0m
                     Time of last status change.

              [1mTAR_SIZE[0m
                     Size of the file.

              [1mTAR_UID[0m
                     UID of the file owner.

              [1mTAR_GID[0m
                     GID of the file owner.

              Additionally, the following variables contain information about [1mtar [22moperation mode and
              the archive being processed:

              [1mTAR_VERSION[0m
                     GNU [1mtar [22mversion number.

              [1mTAR_ARCHIVE[0m
                     The name of the archive [1mtar [22mis processing.

              [1mTAR_BLOCKING_FACTOR[0m
                     Current blocking factor, i.e. number of 512-byte blocks in a record.

              [1mTAR_VOLUME[0m
                     Ordinal  number  of the volume [1mtar [22mis processing (set if reading a multi-volume
                     archive).

              [1mTAR_FORMAT[0m
                     Format of the archive being processed.  One of: [1mgnu[22m, [1moldgnu[22m, [1mposix[22m, [1mustar[22m, [1mv7[22m.

              [1mTAR_SUBCOMMAND[0m
                     A short option (with a leading dash) describing the operation [1mtar [22mis executing.

   [1mHandling of file attributes[0m
       [1m--atime-preserve[22m[=[4mMETHOD[24m]
              Preserve access times on dumped files, either by restoring  the  times  after  reading
              ([4mMETHOD[24m=[1mreplace[22m,  this  is the default) or by not setting the times in the first place
              ([4mMETHOD[24m=[1msystem[22m).

       [1m--delay-directory-restore[0m
              Delay setting modification times and permissions of extracted  directories  until  the
              end  of extraction.  Use this option when extracting from an archive which has unusual
              member ordering.

       [1m--group[22m=[4mNAME[24m[:[4mGID[24m]
              Force [4mNAME[24m as group for added files.  If [4mGID[24m is not supplied, [4mNAME[24m  can  be  either  a
              user  name  or  numeric  GID.  In this case the missing part (GID or name) will be in‐
              ferred from the current host's group database.

              When used with [1m--group-map[22m=[4mFILE[24m, affects only those files whose  owner  group  is  not
              listed in [4mFILE[24m.

       [1m--group-map[22m=[4mFILE[0m
              Read  group  translation map from [4mFILE[24m.  Empty lines are ignored.  Comments are intro‐
              duced with [1m# [22msign and extend to the end of line.  Each non-empty line in [4mFILE[24m  defines
              translation  for  a  single  group.   It  must consist of two fields, delimited by any
              amount of whitespace:

              [4mOLDGRP[24m [4mNEWGRP[24m[[1m:[4m[22mNEWGID[24m]

              [4mOLDGRP[24m is either a valid group name or a GID prefixed with [1m+[22m.  Unless [4mNEWGID[24m  is  sup‐
              plied,  [4mNEWGRP[24m must also be either a valid group name or a [1m+[4m[22mGID[24m.  Otherwise, both [4mNEW‐[0m
              [4mGRP[24m and [4mNEWGID[24m need not be listed in the system group database.

              As a result, each input file with owner group [4mOLDGRP[24m will be stored  in  archive  with
              owner group [4mNEWGRP[24m and GID [4mNEWGID[24m.

       [1m--mode[22m=[4mCHANGES[0m
              Force symbolic mode [4mCHANGES[24m for added files.

       [1m--mtime[22m=[4mDATE-OR-FILE[0m
              Set  mtime  for  added  files.  [4mDATE-OR-FILE[24m is either a date/time in almost arbitrary
              format, or the name of an existing file.  In the latter case the mtime  of  that  file
              will be used.

       [1m-m[22m, [1m--touch[0m
              Don't extract file modified time.

       [1m--no-delay-directory-restore[0m
              Cancel the effect of the prior [1m--delay-directory-restore [22moption.

       [1m--no-same-owner[0m
              Extract files as yourself (default for ordinary users).

       [1m--no-same-permissions[0m
              Apply the user's umask when extracting permissions from the archive (default for ordi‐
              nary users).

       [1m--numeric-owner[0m
              Always use numbers for user/group names.

       [1m--owner[22m=[4mNAME[24m[:[4mUID[24m]
              Force  [4mNAME[24m  as  owner  for added files.  If [4mUID[24m is not supplied, [4mNAME[24m can be either a
              user name or numeric UID.  In this case the missing part (UID or  name)  will  be  in‐
              ferred from the current host's user database.

              When used with [1m--owner-map[22m=[4mFILE[24m, affects only those files whose owner is not listed in
              [4mFILE[24m.

       [1m--owner-map[22m=[4mFILE[0m
              Read  owner  translation map from [4mFILE[24m.  Empty lines are ignored.  Comments are intro‐
              duced with [1m# [22msign and extend to the end of line.  Each non-empty line in [4mFILE[24m  defines
              translation  for a single UID.  It must consist of two fields, delimited by any amount
              of whitespace:

              [4mOLDUSR[24m [4mNEWUSR[24m[[1m:[4m[22mNEWUID[24m]

              [4mOLDUSR[24m is either a valid user name or a UID prefixed with [1m+[22m.  Unless  [4mNEWUID[24m  is  sup‐
              plied, [4mNEWUSR[24m must also be either a valid user name or a [1m+[4m[22mUID[24m.  Otherwise, both [4mNEWUSR[0m
              and [4mNEWUID[24m need not be listed in the system user database.

              As a result, each input file owned by [4mOLDUSR[24m will be stored in archive with owner name
              [4mNEWUSR[24m and UID [4mNEWUID[24m.

       [1m-p[22m, [1m--preserve-permissions[22m, [1m--same-permissions[0m
              Set permissions of extracted files to those recorded in the archive (default for supe‐
              ruser).

       [1m--same-owner[0m
              Try extracting files with the same ownership as exists in the archive (default for su‐
              peruser).

       [1m-s[22m, [1m--preserve-order[22m, [1m--same-order[0m
              Tell  [1mtar  [22mthat  the  list of file names to process is sorted in the same order as the
              files in the archive.

       [1m--sort=[4m[22mORDER[0m
              When creating an archive, sort directory entries according to [4mORDER[24m, which is  one  of
              [1mnone[22m, [1mname[22m, or [1minode[22m.

              The default is [1m--sort=none[22m, which stores archive members in the same order as returned
              by the operating system.

              Using  [1m--sort=name  [22mensures  the member ordering in the created archive is uniform and
              reproducible.

              Using [1m--sort=inode [22mreduces the number of disk seeks made when creating the archive and
              thus can considerably speed up archivation.  This sorting order is supported  only  if
              the underlying system provides the necessary information.
